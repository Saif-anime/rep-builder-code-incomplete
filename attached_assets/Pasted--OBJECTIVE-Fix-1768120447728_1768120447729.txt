========================================
OBJECTIVE
========================================

Fix incorrect Entry/Exit time calculation and duration logic.
Ensure observation times are derived strictly from evidence timestamps.

========================================
UI TERMINOLOGY UPDATE
========================================

In the Analysis section:

- Rename:
  ❌ Entry        → ✅ Observe From
  ❌ Exit         → ✅ Observe To

These labels must reflect actual observation, not inferred entry/exit.

========================================
TIME EXTRACTION LOGIC (CRITICAL)
========================================

When analysing an evidence bundle:

1️⃣ Collect timestamps from ALL evidence files in the bundle:
   - Images (EXIF DateTimeOriginal if available)
   - Videos (recorded_at / metadata timestamp)
   - Fallback: system upload time ONLY if metadata missing

2️⃣ Sort all valid timestamps chronologically.

3️⃣ Assign:
   - Observe From = earliest valid timestamp
   - Observe To   = latest valid timestamp

⚠️ Never assume same entry & exit time
⚠️ Never infer duration without timestamps

========================================
DURATION CALCULATION
========================================

Duration = Observe To - Observe From

Rules:
✔ Display in hours & minutes
✔ Always non-negative
✔ Validate against site max stay rules
✔ Recalculate duration every time evidence changes

If timestamps are invalid or missing:
- Show warning: "Insufficient timestamp data for duration accuracy"
- Do NOT generate PCN automatically

========================================
ANALYSIS DEPENDENCY
========================================

All downstream analysis MUST use:
✔ Observe From
✔ Observe To
✔ Calculated Duration

This includes:
- Maximum stay validation
- Grace period checks
- Enforcement hour checks
- PCN eligibility decision
